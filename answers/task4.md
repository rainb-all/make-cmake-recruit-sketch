# Task 4：思考题

## 1. Make 和简单的 build.sh 有什么区别？假设 build.sh 只是把所有 gcc 命令从头到尾执行一遍，Make 相比这种方式有什么优势？

- 区别：`build.sh`在每次的运行中都会无条件地执行全部的gcc编译命令，无论源码有没有进行改动，都会全部重新编译；但是Make会根据文件修改时间，判断目标文件和依赖文件的新旧关系，接着只重新编译被修改过的文件，这就是增量编译的优点。在task2中touch后有体现其优点。

- 优势：
    - 增量编译只去编译改动的相关文件，节省了编译时间，在文件很多时优势明显。
    - 可以自动维护文件的依赖关系，会自动判断需要重建的部分。
    - 内置clean，方便清理产物。

## 2. CMake 是编译器吗？执行 `cmake --build build` 时，最终是谁在编译 C 源文件？

- 本身不是编译器，CMake的作用时读取CMakeLists.txt，生成底层构建文件，本身不具有编译器功能。
- cmake只是在调用底层构建工具，真正是调用了gcc编译器，由gcc将C源代码编译链接为机器码和可执行程序。

## 3. 为什么不希望每次都重新编译所有 `.c` 文件？
- 如果全部重新编译会浪费大量的时间，效率低下；同时若只是修改一个文件，其他的49个均未发生变化，重新编译后与之前的并无差别，因此也没有意义去浪费很多内存资源、占用更多的CPU，做重复的无意义工作。
